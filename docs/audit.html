F-14 With the sessions folder missing, the feed watch tries to open it every second for as long as the app runs

low fixed users may notice it

Requirements: V15.1.3

Where: Sources/Feed/FolderWatch.swift:40-48; Sources/App/Controller.swift:156, 221-225

What was found: FolderWatch.watch calls open(path, O_EVTONLY) and, when that fails, schedules itself again after retry, 1 s by default, with no limit while the watch is active (FolderWatch.swift:40-48). Controller starts the watch at every launch whatever the hook state (Controller.swift:156) with the default retry (Controller.swift:221). The sessions folder is made only by Install or the hook script (Hook.swift:186) and deleted by Remove (Hook.swift:259). So an app running before Install, or started again after a Remove, wakes once a second for good, next to its 5 s feed timer and 10 s Mac timer. Remove in the same run stops the watch (Controller.swift:676), so that case is covered. In 0.1.15 the watch simply did not start when the folder was missing (git show v0.1.15:Sources/App/Controller.swift:223-224). New in 0.1.16. Not measured on a running app (the rules of this check forbid running it against the real data folder); the cost per wake is one failed open, so the effect is energy and timer wakes, not visible in normal use. docs/spec.html:155 says the watch is tried again every second until the hook script has made the folder, but not that this runs without end while the hook is not installed, so V15.1.3 is met for the hot path only.

The fix: Retry with a growing delay (for example up to 60 s), or let the 5 s feed timer restart the watch when the folder appears, or start the watch only once the hook is installed; add a test that a missing folder does not wake the queue every second.

The verifier: found by the verifier (V-1). Re-checked at f2e9691: FolderWatch.delay gives retry times 2 to the power of misses, capped at maxRetry 60 s and the exponent at 30 (FolderWatch.swift:30-33); watch counts misses on each failed open and resets them to 0 when the watch is made (FolderWatch.swift:54-62), so a deleted folder is still tried after 1 s first. Install makes the folder and starts a new FolderWatch, so it is watched at once. Test aMissingFolderIsTriedLessAndLessOften checks 1, 2, 4 ... 32, 60, 60 and the edges; it and theFolderWatchSurvivesTheFolderBeingDeletedAndMadeAgain pass, 271 tests in 16 suites at f2e9691 in the Mac zone and UTC (a separate worktree, removed after). Wakes while the folder is missing drop to one a minute after about two minutes. Fixed on the code; not measured on a running app.

6 How it is done

Before every release, in this order:

  1. Scope: the commit, the last audited tag, and what the app exposes. tokenpanda has no network listener and makes no network calls; it reads Claude Code's status line feed, the transcripts and settings.json, and writes its own data folder and, on a click, one key of settings.json.
  2. Scanners, as in section 5.
  3. An AI agent reads the code against every requirement in scope and sets pass, fail or does not apply, with evidence. A full audit covers every requirement at Level 2; a release audit covers every requirement the change touches, and the rest keep their result from the audit before.
  4. A second AI agent, which did not write the findings, checks each one again in the code and by experiment, re-checks a sample of the passes, and confirms, changes or drops each finding.
  5. The release gate: no release with an open blocker or high finding, or with any open finding that users may notice, unless the maintainer decides otherwise in writing. Those decisions are marked accepted above.

Next to ASVS it checks our own list, grouped by the ISO/IEC 25010 quality characteristics (stability, reliability, maintainability and the rest), and platform checks for a Mac app: signing, notarisation, the hardened runtime, entitlements, Apple's interface guidelines, accessibility and the privacy manifest. Those checks are ours and are named as ours; ISO's own text is not quoted.

What this does not give: AI agents can miss things a person would find, and nobody outside the project has checked this work. If you find something, the security advisory form reaches me privately.
